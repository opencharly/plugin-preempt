# 2026.266.0606 — feat: relocate the preempt arbiter beds from distro-fedora

## Summary of changes

Relocate the three resource-arbiter R10 witness beds — `check-preempt-arbiter-pod`, `check-preempt-live-pod`, `check-preempt-vm-live` — from `opencharly/distro-fedora` into this plugin's owning repo, with the self-contained fixture they need.

**WHY.** A check bed must live in the repo that owns what it tests. These beds exercise `candy/plugin-preempt`'s `verb:arbiter` (and, via the arbiter's dispatch, the `command:preempt` surface). The check-bed runner's dev-tree override (`proc.SelfSuperprojectOverridePair`, `spec/proc/repo_override.go`) points the bed PROJECT's own superproject's `@github` refs at the local tree. In the umbrella every submodule's superproject is `opencharly/opencharly` (which hosts no candies), so a candy owned by another repo was never exercised as in-development code while its witness sat in `distro-fedora`. Relocated here, the beds compose the LOCAL `plugin-preempt` candy with no `@github` pin.

**Self-contained fixture (the `plugin-mise` bed-image pattern).** The beds need only a STEADY-STATE pod to hold a synthetic selector-less lock, so this repo declares its own minimal fixture instead of depending on `distro-fedora`'s shared `check-pod`:
- `check-preempt-keepalive` — a **candy** (layer) pinning the current `layer-supervisord` and running a `sleep infinity` keepalive program; carries a `plan:` with a deterministic `check:`.
- `check-preempt-fixture` — a **box/image** (`base: quay.io/fedora/fedora:43`) composing that layer; carries its own `plan:` with a build-context `check:` (`fixture-supervisord-present`).
- `web-vm` — the local `kind:vm` template the VM-venue bed's holder member uses (`cloud_init` installs only `qemu-guest-agent`, which the holder needs for libvirt lifecycle).

**Changed files:**
- `charly.yml` — adds:
  - a `defaults:` block (`platform: [linux/amd64]`, `tag: auto`, `registry: ghcr.io/opencharly`, `build: [rpm]`, `merge: {auto: false, max_mb: 128}`) — the build/registry/merge defaults the beds need to build their fixture image; this IS a build/registry/merge emission change (see R8 below), not a no-op.
  - the fixture (`check-preempt-keepalive` candy + `check-preempt-fixture` box) and the 3 beds (`check-preempt-arbiter-pod`, `check-preempt-live-pod`, `check-preempt-vm-live`) with their holder/taker members and the `web-vm` template, retargeted from `image: check-pod` → `image: check-preempt-fixture`;
  - migrates the `version:` stamp to the schema head.
  - Entity names added: `check-preempt-keepalive`, `check-preempt-fixture`, `check-preempt-arbiter-pod`, `check-preempt-live-pod`, `web-vm`, `check-preempt-vm-live`. **No overlap** with the sibling PR #7 (`check-preempt-app`/`check-preempt-local`) — disjoint entity names, additive blocks on disjoint lines.
- `.gitignore` — the standard generated-artifact rules (`.build/`, `.check/`, `.containerignore`, `.dockerignore`, `output/`, `image/` — the VM bed's `charly vm build` output dir — and editor scratch).
- `.github/workflows/deploy.yml` — CI charly pin `v2026.238.1242` → `v2026.256.1316` (the old pin rejects the schema-head version; the same pin the merged `plugin-pod` precedent and PR #7 use).

**Distinct per-bed tokens (R1/R4 fix).** Each bed owns its OWN synthetic selector-less lock: `check-preempt-arbiter-pod` claims `arbiter-test-lock`, `check-preempt-live-pod` uses `live-test-lock` (holder holds + taker requires), `check-preempt-vm-live` uses `vm-test-lock`. No sibling claims the same resource, so a concurrent roster run has no cross-bed contention.
