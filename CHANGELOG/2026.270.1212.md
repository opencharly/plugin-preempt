# 2026.270.1212 — fix(preempt)!: ship a self-contained CUE schema (no schema-less plugin)

## Summary

Restore `plugin-preempt`'s **own self-contained CUE schema**. `NewMeta` passed a `nil` schema FS and served an **EMPTY** schema — the SDK's former *"input-less plugin"* waiver. There is no schema-less plugin: every plugin presents the same CUE-validated, code-generated surface, even where a capability's authored input is its pass-through CLI grammar rather than a structured `plugin_input`.

This is the **plugin-preempt leg** of the R5 cutover tracked in **opencharly/charly#712** (the sdk contract landed as **opencharly/sdk#314**).

### Files

- `candy/plugin-preempt/schema/preempt.cue` — the plugin's OWN self-contained schema (`#PreemptPlugin`): documents the `verb:arbiter` + `command:preempt` capability pair. It references no base def, so it compiles **standalone** (the property `cue exp gengotypes` needs and the property that lets the SDK compile it serve-side), and splices `base ++ plugin` at the host load gate.
- `candy/plugin-preempt/plugin.go` — `//go:embed schema/*.cue` + `sdk.NewMeta(calver, caps, schemaFS)`; the stale schema-less comment corrected.
- `candy/plugin-preempt/schema_serve_test.go` — `Describe` MUST carry a non-empty `schema_cue` (fails without the change).

**Refs:** opencharly/charly#712
